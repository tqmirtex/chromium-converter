# ファイル変換(Chrome 拡張機能)

ファイルの形式を、**ブラウザの中だけで**変換する Chrome 拡張機能(Manifest V3)です。画像・文書・表計算・PDF・音声・動画・フォント・アーカイブの変換に対応しています。

## 特徴

- **完全ローカル処理**:ファイルの内容・ファイル名・利用状況をインターネットに送信しません。変換に使うライブラリ・wasm・フォントはすべて拡張機能に同梱しており、CDN や解析ツールには接続しません。
- **かんたん操作**:ツールバーのアイコンでサイドパネルを開き、ファイルをドロップ(または貼り付け)して変換先を選ぶだけです。変換先の候補には、それぞれ「写真向け」「Web 掲載向け」のような用途が出ます。ウェブページ上の画像は、右クリックからそのまま変換して保存できます。
- **品質を落とさない**:劣化しない変換は劣化なしで、劣化する形式へは高品質の設定で書き出します。動画や音声は、できるだけ再エンコードせずに詰め替えます。
- **まとめて変換**:複数のファイルを一度に変換し、個別・フォルダ・ZIP のいずれかで保存できます。
- **最小限の権限**:ウェブページを読む権限は、右クリック変換を初めて使うときにだけ求めます。
- UI は日本語のみです。対象ブラウザは Chrome(117 以降)です。

## 導入方法(インストール)

Chrome ウェブストアには公開していません。ソースからビルドして、Chrome に「パッケージ化されていない拡張機能」として読み込みます。

### 必要なもの

- [Google Chrome](https://www.google.com/chrome/) 117 以降
- [Node.js](https://nodejs.org/) 20.19 以上、または 22.12 以上(npm が同梱されています)
- [Git](https://git-scm.com/)(リポジトリを取得する場合。ZIP でダウンロードしてもかまいません)

### 手順

1. リポジトリを取得します。
   ```bash
   git clone <このリポジトリの URL>
   cd <取得したフォルダ>
   ```
   GitHub の「Code」→「Download ZIP」でダウンロードし、展開してもかまいません。
2. 依存パッケージを入れて、ビルドします。`dist` フォルダができます。
   ```bash
   npm install
   npm run build
   ```
3. Chrome のアドレスバーに `chrome://extensions` と入力して開き、右上の「デベロッパー モード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押し、手順 2 でできた **`dist` フォルダ**を選びます。
5. ツールバーのパズルのアイコン(拡張機能)から「ファイル変換」をピン留めしておくと、すぐに開けます。

### 更新するとき

```bash
git pull
npm install
npm run build
```

そのあと `chrome://extensions` で「ファイル変換」の再読み込みボタン(円の矢印)を押します。

### アンインストール

`chrome://extensions` で「ファイル変換」の「削除」を押します。右クリック変換で許可した権限も一緒に消えます。

## 使い方

### サイドパネル

1. ツールバーの拡張機能アイコンを押すと、右側にサイドパネルが開く。
2. ファイルを追加する。方法は3つ。
   - パネルにドラッグ&ドロップする
   - 「ファイルをドロップ」の枠をクリックして選ぶ
   - エクスプローラーなどでコピーしたファイルを、パネル上で `Ctrl+V`(Mac は `Cmd+V`)で貼り付ける
3. 「変換先」から形式を1つ選ぶ。各形式の右に、どんな用途に向いているかが出る。
4. 複数のファイルを変換するときは「保存方法」を選ぶ(下記)。画像を PDF にするときは「PDFの作り方」も選ぶ(下記)。
5. 「変換してダウンロード」を押す。変換が終わると保存される。

- 一覧の「×」で個別に外せます。
- 一覧は、各項目の上下ボタン(キーボードでも操作できます)か、ドラッグで並べ替えられます。
- 種類の違うファイルを混ぜたときは、**全部が変換できる形式だけ**が候補に出ます。すでにその形式のファイルは「変換不要」としてそのままにします。
- 変換中は「キャンセル」で中止できます(キャンセルしたときはファイルを保存しません)。
- 一部のファイルが失敗しても、成功したものは保存します。失敗したファイルは一覧に理由が残ります。
- 各ファイルの状態は「待機」「変換中」「完了」「変換不要」「失敗」(追加時に「未対応」「対象外」)を、文字とアイコンで表示します。
- 形式は拡張子だけでなく、ファイルの先頭のバイト(中身)でも判定します。拡張子と中身が違うときは中身を優先します。判定できない形式は「未対応」と表示し、変換の対象から外します。

#### 保存方法(出力が2つ以上のとき)

| 選択 | 保存先 |
|---|---|
| 個別にダウンロード | ダウンロード先に1ファイルずつ |
| 一括でフォルダにダウンロード | 「変換してダウンロード」を押したときに**保存先のフォルダを1回選び**、そのフォルダにすべてのファイルを保存 |
| 一括 + 「ZIPにまとめる」 | 選んだフォルダに `ファイル変換_日付_時刻.zip`(例:`ファイル変換_20261117_103015.zip`)を1つ保存 |

- **一括保存では、フォルダを1回選ぶだけで、ファイルごとの確認は出ません。** Chrome の設定「ダウンロード前に各ファイルの保存場所を確認する」がオンでも同じです(Chrome のダウンロード機能ではなく、ブラウザのファイル保存の仕組み=File System Access API で直接書き込むため)。フォルダの選択画面は、前回選んだ場所から開きます。
- 選んだフォルダに同じ名前のファイルがあるときは、**上書きせず** `写真 (1).png` のように番号を付けて保存します。
- フォルダを選ばずに閉じたときは、変換しません。
- 出力が1つだけのときは、選択を出さずにそのまま保存します。
- 「個別にダウンロード」は Chrome のダウンロード機能で保存します。保存ダイアログは出しませんが、Chrome の設定「ダウンロード前に各ファイルの保存場所を確認する」がオンのときは、ファイルごとに確認が出ます。
- 選んだ保存方法は次回も使われます。
- ZIP 内のファイル名は UTF-8 で記録し、UTF-8 フラグを付けています(Windows のエクスプローラー・macOS で日本語名が文字化けしません)。ZIP 内で名前が重なったときは `写真 (1).png` のように番号を付けます。PNG・JPEG などすでに圧縮された形式は、ZIP では再圧縮せずそのまま格納します。

#### PDFの作り方(画像を2枚以上 PDF にするとき)

- **画像ごとに別のPDFにする**:画像1枚につき PDF を1つ作ります。
- **1つのPDFにまとめる**:一覧の順に1ページずつ並べた PDF を1つ作ります。ファイル名は**一覧の先頭のファイルの名前**に `.pdf` を付けたものです。読み込めない画像があったときは、その画像を除いてまとめ、一覧に理由を残します。

### 右クリック(ウェブページ上の画像)

1. ウェブページ上の画像を右クリックする。
2. メニューの「ファイル変換」から「〇〇に変換」を選ぶ。
3. 画像を取得して変換し、ダウンロード先に保存する(サイドパネルは開かない)。変換が終わると「変換が完了しました」と通知が出る(Chrome の設定で保存場所を確認するようにしている場合は、通知のあとに保存ダイアログで保存する)。

- **初回だけ**、ウェブ上の画像を読み込む権限の確認が出ます(下記「権限と理由」)。
- ファイル名は画像 URL のファイル名の拡張子だけを変えます(例:`.../photo.webp?w=800` → `photo.png`)。URL から名前が取れないとき(`data:` URL など)は `image` になります。
- 取得した画像がすでにその形式だったときは、「変換不要」と通知して保存しません。
- メニューには、画像の形式に関係なく変換先の全形式が出ます(Chrome の右クリックメニューは、URL の拡張子で項目を出し分けられないため)。変換できない組み合わせを選んだときは、理由を通知します。
- `data:` URL の画像は扱えます。`blob:` URL の画像(ページ内で作られた画像)は取得できないため、失敗として通知します。パソコン内の画像(`file:`)はサイドパネルにドラッグしてください。

### ファイル名

- 拡張子だけが変わります(例:`写真.heic` → `写真.jpg`)。
- 同じ名前のファイルがあるときは、Chrome が自動で `写真 (1).jpg` のように番号を付けます。
- 例外は2つだけです。PDF → 画像で複数ページあるときは `資料_001.png`、`資料_002.png` … のようにページ番号を付けます(1ページだけなら `資料.png`)。複数の画像を1つの PDF にまとめるときは、先頭のファイルの名前に `.pdf` を付けます。
- Excel の複数シート・Markdown の複数の表を分けて出力するときは、`元の名前_シート名.csv` のように付けます。

## 対応する変換

### 画像

| 変換元 | 変換先 |
|---|---|
| WebP | PNG / JPEG |
| PNG | JPEG / WebP / AVIF / ICO |
| JPEG | PNG / WebP / AVIF |
| AVIF | PNG / JPEG |
| SVG | PNG / JPEG / WebP |
| HEIC / HEIF | JPEG / PNG |
| ICO | PNG |
| BMP / TIFF / GIF(静止画) | PNG / JPEG |

### ドキュメント・テキスト

| 変換元 | 変換先 |
|---|---|
| Markdown(.md) | HTML / PDF / テキスト(.txt) / CSV(文書中の表を取り出す) |
| HTML | Markdown(.md) / テキスト(.txt) |
| JSON | YAML / TOML / CSV / Excel(.xlsx) |
| YAML / TOML | JSON |
| CSV | JSON / TSV / Markdownテーブル / Excel(.xlsx) / 別の文字コードの CSV |
| TSV | CSV / Excel(.xlsx) |

### 表計算・データ

| 変換元 | 変換先 |
|---|---|
| Excel(.xlsx / .xls) | CSV / TSV / JSON |
| CSV(Shift-JIS) | CSV(UTF-8) / CSV(UTF-8 BOM付き) |
| CSV(UTF-8 / UTF-8 BOM付き) | CSV(Shift-JIS)、および UTF-8 ⇔ UTF-8 BOM付き |

### PDF

| 変換元 | 変換先 |
|---|---|
| PNG / JPEG / WebP | PDF(画像ごとに別の PDF、または1つの PDF にまとめる) |
| PDF | PNG / JPEG(1ページ1枚) / テキスト(.txt) |
| Markdown(.md) | PDF(日本語対応) |

### 音声・動画

| 変換元 | 変換先 |
|---|---|
| 動画(MP4 / WebM / MOV / MKV) | 音声(MP3 / WAV / M4A / OGG) |
| 動画(MOV / MKV / WebM) | MP4 |
| 動画(MP4 / WebM / MOV / MKV) | アニメーション GIF / アニメーション WebP |
| WAV / FLAC / OGG / M4A / AAC | MP3 |
| MP3 | WAV / FLAC / OGG / M4A / AAC |

AVI は対象外です(下記「音声・動画変換の詳細」)。

### フォント

| 変換元 | 変換先 |
|---|---|
| TTF / OTF | WOFF / WOFF2 |
| WOFF / WOFF2 | TTF / OTF(元の輪郭の形式に合わせて選ぶ) |

### アーカイブ

| 変換元 | 変換先 |
|---|---|
| ZIP | TAR / TAR.GZ |
| TAR / TAR.GZ | ZIP |

CSV は拡張子が同じ `.csv` なので、候補には「CSV(UTF-8)」「CSV(UTF-8 BOM付き)」「CSV(Shift-JIS)」と文字コードを付けて出します。CSV に変換するときは、この3つから選べます。

## 品質の方針

- 劣化しない変換は劣化なしで行います(例:PNG → WebP はロスレス WebP、JPEG → PNG、ICO ⇔ PNG、TIFF・BMP → PNG)。
- 劣化する形式へは高品質の設定で書き出します。

| 書き出し | 設定 |
|---|---|
| JPEG | 品質 0.95 |
| WebP(JPEG から) | 品質 0.95 |
| WebP(PNG・SVG から) | ロスレス |
| AVIF | 品質 90(PNG・SVG などから:色の間引きなし 4:4:4、JPEG から:4:2:0) |

### 品質が下がりうる組み合わせ

- **→ JPEG**(PNG・WebP・AVIF・SVG・HEIC・BMP・TIFF・GIF から):JPEG は非可逆圧縮です。透過部分は白で塗りつぶします(完了時に表示します)。
- **JPEG → WebP / AVIF**:非可逆の再圧縮になります。
- **PNG → AVIF**:非可逆圧縮です(ロスレス AVIF は PNG より大きくなりやすいため)。
- **PNG → ICO**:ICO の上限が 256×256 のため、それより大きい画像は縮小します。正方形の画像は 16〜256px の標準サイズを複数入れます。
- **アニメーション GIF / WebP / AVIF / PNG(APNG)→ 静止画**:最初のフレームだけを使います(完了時に表示します)。
- **複数ページの TIFF、複数画像を含む HEIC**:最初の1枚だけを変換します(完了時に表示します)。
- **ICO → PNG**:ICO に含まれるサイズのうち最も大きいものを使います。
- **PDF → JPEG**:非可逆圧縮です(品質 0.95)。文字の多い PDF は PNG のほうがくっきりします。
- **PDF → PNG / JPEG**:ページを 200dpi で画像にします(下記)。拡大すると元の PDF ほどは精細ではありません。
- **音声を MP3 / AAC / OGG にする変換**:非可逆圧縮です(元のビット率を下回らない設定にします)。
- **動画 → MP4 で再エンコードが必要なとき**(VP8・VP9・AV1・Opus など):H.264 + AAC に変換するため、わずかに劣化します。
- **動画 → GIF / アニメーション WebP**:幅・フレームレート・長さを減らし、GIF は 256 色に減色します。
- **WebP → PDF**:PDF は WebP を扱えないため、一度展開して劣化のない形式で埋め込みます(画質は変わりませんが、ファイルは大きくなることがあります)。

### その他

- **メタデータ(Exif など)は保持しません。** 撮影日時や位置情報は出力に残りません。写真の向き(Exif の回転)は画像に反映してから書き出します。
- 色は sRGB で書き出します。広色域の写真では色がわずかに変わることがあります。
- SVG は、寸法が小さい・書かれていない場合、長辺 1024px で画像にします(ベクターなので粗くはなりません)。長辺の上限は 8192px です。SVG 内のスクリプトは実行されず、外部の画像やフォントは読み込みません。

## ドキュメント・データ変換の詳細

### 文字コード

- **読み込み**:BOM があればそれに従います。BOM がなければ、UTF-8 として正しく読めれば UTF-8、読めなければ Shift-JIS(Windows-31J)とみなします。日本語を含む文章が「UTF-8 としても Shift-JIS としても正しい」ことはまずないため、選択画面は出さず自動で判定します。英数字だけのファイルはどちらでも同じ内容なので UTF-8 として扱います。UTF-8・Shift-JIS 以外(EUC-JP や BOM なし UTF-16 など)は「文字コードを判別できませんでした」と表示します。
- **書き出し**:CSV は選んだ文字コード、それ以外(JSON・YAML・TOML・Markdown・HTML・テキスト・TSV)は UTF-8(BOM なし)で書き出します。
- **Shift-JIS で表せない文字**(「𠮷」などの一部の漢字・絵文字など)があるときは、**勝手に置き換えず、変換を失敗にします**。失敗表示に、その文字と行番号を出します。CSV(UTF-8 BOM付き)を選べば Excel でも文字化けせずに開けます。
- JIS と Windows で割り当ての違う記号(「−」マイナス記号、「〜」波ダッシュ、「‖」「¢」「£」「¬」「—」)は、Shift-JIS では Windows 側の文字(「－」「～」「∥」「￠」「￡」「￢」「―」)として書き出します。
- CSV の文字コードだけを変えるときは、中身(区切り・引用符・改行コード)を一切変えずに書き直します。

### CSV / TSV

- CSV は RFC 4180 に沿って読み書きします(引用符で囲んだセル、セル内のカンマ・改行・引用符に対応)。書き出しの改行は CRLF です。
- CSV → JSON は、1行目を見出しとしてオブジェクトの配列にします。値はすべて文字列のままにします(`001` のような番号を壊さないため)。見出しが空のときは「列1」…、重複しているときは「名前_2」のように補います。
- CSV → Markdownテーブルは、1行目を見出しにします。セル内の `|` は `\|` に、改行は `<br>` にします(Markdown → CSV では `<br>` を改行に戻します)。
- CSV / TSV → Excel では、数字だけのセルは数値にします。ただし `001` のように 0 で始まるものや 16 桁以上のものは、電話番号・郵便番号・ID を壊さないよう文字のままにします。

### JSON と表(CSV・Excel)の形

JSON → CSV / Excel は、次の形を受け付けます。

```json
[
  { "名前": "山田", "年齢": 30 },
  { "名前": "佐藤", "年齢": 25, "メモ": "追加の列" }
]
```

- オブジェクトの配列:キーを登場順に並べて見出しにします(途中で増えたキーも列になります)。
- 配列の配列(`[["名前", "年齢"], ["山田", 30]]`):そのまま行にします。
- オブジェクト1つ:1行の表にします。
- 入れ子のオブジェクト・配列は、JSON の文字列としてセルに入れます。
- それ以外(文字列や数値だけなど)は、理由を表示して失敗にします。

Excel → JSON は、各シートの1行目を見出しとしたオブジェクトの配列にします。数値・真偽値はそのまま、日付は `2026-11-17`(時刻があれば `2026-11-17 10:30:00`)の文字列、空のセルは `null` にします。

### Excel

- **シートが複数あるとき**は、Excel → CSV / TSV / JSON で**シートごとに1ファイル**を出力し、名前は `元の名前_シート名.csv` にします(シートが1つなら `元の名前.csv`)。複数のファイルは、サイドパネルの「保存方法」(個別・フォルダ・ZIP)で保存できます。空のシートは出力しません。
- **数式は計算結果の値**で出力します(Excel が最後に保存したときの値)。数式そのものは出力しません。
- CSV / TSV に書き出す値は、Excel での表示どおりの文字です(書式を反映)。日付の標準書式は `2026-11-17` の形にそろえます。
- CSV / TSV / JSON → Excel は1シート(シート名は元のファイル名)です。
- パスワード付きの Excel ファイルは読み込めません。Excel 95 以前の古い .xls は、文字化けすることがあります。
- セル内の改行は、Excel の仕様で LF(`\n`)になります。

### Markdown → HTML

- 出力は1ファイルで開ける HTML です。最小限のスタイル(本文の幅・見出し・表の罫線・コードの背景)を埋め込み、外部の CSS やフォントは読み込みません。
- 文中に書かれた生の HTML(`<script>` など)は**タグとして解釈せず、文字として表示**します。`javascript:` などの危険なリンクは無効にします。
- 表(GitHub 形式)・コード・引用・リストに対応します。

### HTML → Markdown / テキスト

- HTML はブラウザの DOMParser で読み込みます。**画面には表示せず、スクリプトは実行されず、画像などの外部リソースも読み込みません。**
- `script`・`style`・`noscript`・`iframe` などは取り除いてから変換します。
- 表は Markdown の表にします(セル内の書式は外します)。

## PDF 変換の詳細

### 画像 → PDF

- **画像は再圧縮しません。** JPEG はデータをそのまま PDF に埋め込みます。PNG は画素を劣化させずに(可逆圧縮で)埋め込み、**透過も保ちます。**
- ページの大きさは、画像のピクセル数と解像度(dpi)から決めます。画像はページいっぱいに収まり、余白は付けません。縦長の画像は縦向き、横長の画像は横向きのページになります。
  - 解像度は、JPEG は JFIF / Exif、PNG は pHYs に書かれた値を使います。書かれていないときは 96dpi とみなします(例:1920×1080 の画像は 20×11.25 インチのページ)。
- スマートフォンの写真などの向き(Exif の回転)は、PDF の上で回転して正しい向きにします(画像データは変えません)。

### PDF → 画像

- **解像度は 200dpi** です(A4 のページが約 1654×2339 ピクセル)。小さな文字も読める細かさで、1ページあたりのファイルサイズとメモリ使用量を抑えられる値として選びました。
- 背景は白にします。
- ページを1枚ずつ描いて、そのたびにメモリを解放します。進み具合はページ単位で表示します(例:「12 / 40 ページ」)。
- とても大きいページ(4000万ピクセル超、または一辺 16000 ピクセル超)は、メモリを使い切らないよう解像度を下げます(完了時に表示します)。
- 出力が複数になるときは、「保存方法」(個別・フォルダ・ZIP)で保存できます。

### PDF → テキスト

- PDF に含まれる文字のデータを取り出します。ページの間は空行で区切ります。
- **スキャンした画像だけの PDF は、文字のデータがないため取り出せません**(画像の中の文字を読み取る OCR には対応していません)。そのときは理由を表示します。一部のページだけ文字がないときは、その旨を表示します。
- 段組みや表の多い PDF では、文字の並び順が見た目と違うことがあります。

### パスワード付き・壊れた PDF

- パスワード付きの PDF は「パスワード付きのPDFは変換できません」、壊れた PDF は「ファイルが壊れている可能性があります」と表示します。

### Markdown → PDF

- 用紙は A4 縦、余白は約 20mm、本文は 10.5pt です。下中央にページ番号(「1 / 3」)を入れます。
- 見出し・段落・太字・斜体・取り消し線・インラインコード・コードブロック・引用・リスト(入れ子・番号付き)・リンク(クリックできます)・表・区切り線に対応します。
- **日本語フォント**:Noto Sans JP(Regular、SIL Open Font License 1.1)を拡張機能に同梱しています(約 5.7MB)。PDF には**実際に使った文字の形だけ**を埋め込むので、出力は日本語の文書でも数十〜数百 KB です。
- 太字は、太字用のフォントを同梱せず(サイズを抑えるため)、文字の輪郭を描き足して太く見せます。斜体は文字を傾けて表します。
- コードの英数字は等幅の Courier(PDF の標準フォントで埋め込み不要)、日本語は Noto Sans JP で描きます。
- 行頭に「、。」などが来ないよう、簡単な禁則処理をします。英単語は途中で切りません(1行に収まらない長い URL などは文字単位で折り返します)。
- **画像は読み込みません**(外部への通信をしないため)。代わりに `[画像: 説明文]` と表示します。
- 絵文字など、Noto Sans JP にない文字は表示されません(完了時に表示します)。
- 文中の生の HTML はタグとして解釈せず、文字として表示します。

## 音声・動画変換の詳細

### 仕組み

- ブラウザ標準の **WebCodecs**(映像・音声の展開と圧縮)と、**Mediabunny**(MP4・WebM などの読み書き)で変換します。ハードウェアを使えるので、多くの場合は実時間より速く終わります。
- ブラウザにエンコーダーがない **MP3・FLAC・AAC** は、同梱のエンコーダー(LAME・libFLAC・FFmpeg の AAC エンコーダーを wasm にしたもの)で書き出します。AAC はブラウザにもエンコーダーがありますが、環境によって使えるビット率が限られる(Windows では 192kbps まで)ため、同梱のものにそろえています。
- 複数の音声トラックがあるファイル(MKV など)は、主な音声トラックだけを使います。字幕は出力しません。

### 品質の方針

- **形式が同じ音声・映像は、再エンコードせずにそのまま詰め替えます(劣化なし)。** 例:H.264 + AAC の MOV / MKV → MP4、MP4(AAC)→ M4A、WebM(Opus)→ OGG。完了時に「再エンコードせずに…」と表示します。
- **動画 → MP4**:映像が H.264 / HEVC、音声が AAC / MP3 ならそのまま詰め替えます。それ以外(VP8・VP9・AV1・Opus など)は、どの機器でも再生しやすいよう H.264 + AAC に変換します。WebCodecs には CRF の指定がないため、映像は「CRF 18 前後」に相当する高めのビット率(Mediabunny の `QUALITY_VERY_HIGH`)にしています。
- **非可逆の音声(MP3 / AAC / Opus)へは、元のビット率を下回らない設定**にします。

| 書き出し | ビット率の決め方 |
|---|---|
| MP3 | 元のビット率以上で最も近い値(128 / 160 / 192 / 224 / 256 / 320kbps)。元が WAV・FLAC などの劣化なしの形式なら 320kbps |
| AAC(M4A / AAC) | 元のビット率以上で最も近い値(128 / 160 / 192 / 256 / 320kbps)。元が劣化なしの形式なら 256kbps |
| Opus(OGG) | 元のビット率以上で最も近い値(128〜510kbps)。元が劣化なしの形式なら 256kbps |
| WAV | 16bit PCM(劣化なし) |
| FLAC | 劣化なし |

- MP3・AAC・Opus は2チャンネルまでなので、5.1ch などはステレオにまとめます。MP3・AAC は 48kHz まで、Opus は常に 48kHz で書き出します(完了時に表示します)。
- MP3 などの圧縮音声を WAV / FLAC にしても、音質は元のままです(良くはなりません)。
- **OGG は Ogg Opus**(拡張子 .ogg)で書き出します。Vorbis のエンコーダーがないためです。Opus は Vorbis より高音質・小サイズで、主なプレーヤーで再生できます。

### 動画 → アニメーション GIF / WebP

ファイルが大きくなりすぎないよう、次の上限で作ります(完了時に表示します)。

| | 幅 | フレームレート | 長さ |
|---|---|---|---|
| GIF | 480px まで(縦は比率を保つ) | 10fps | 最初の 15 秒まで |
| WebP | 640px まで | 15fps | 最初の 15 秒まで |

- 小さい動画は拡大しません。
- **GIF は 256 色に減色する**ため、写真のような映像は色がざらつきます。WebP は非可逆圧縮(品質 0.8)で、GIF より高画質で軽くなります。
- いずれも無限ループです。

### 対応していないもの

- **AVI** は読み込めません(「AVI からの変換には対応していません」と表示します)。
- ブラウザが展開できない映像・音声の方式(DivX / Xvid、WMV、ProRes、AC-3 / DTS など)を含むファイルは、理由を表示して失敗にします。
- 音声の入っていない動画を音声にしようとしたときは「この動画には音声が入っていません」と表示します。

### 処理時間の目安

パソコンの性能やハードウェアの対応状況によって大きく変わります。

| 変換 | 目安 |
|---|---|
| 詰め替えだけ(MOV → MP4 など) | ファイルの読み書きの時間だけ(数秒) |
| 音声の変換 | 数十倍速(5 分の曲で数秒〜十数秒) |
| 映像の再エンコード(WebM → MP4 など) | 実時間の数分の1〜同程度(10 分の 1080p 動画で数分) |
| GIF / WebP | 15 秒の動画で数秒〜十数秒 |

- 進み具合は割合と経過時間(例:「1:23 / 5:00」、GIF / WebP は「120 / 150 コマ」)で表示し、「キャンセル」で中止できます。
- **変換中にサイドパネルを閉じると、変換は中断されます**(ファイルは保存されません)。変換中はその旨をパネルに表示します。

## フォント・アーカイブ変換の詳細

### フォント

- **グリフ・メトリクス・ヒンティングなどの表は変えません。**
  - **WOFF**:各表を zlib で圧縮して包むだけです。WOFF → TTF / OTF に戻すと、元のファイルとバイト単位で同じになります(標準的な配置のフォントの場合)。
  - **WOFF2**:brotli で圧縮します。書き出しは glyf / loca 表を「変換なし」(WOFF2 の規格の transform version 3)で格納するため、元に戻すと表のデータはすべて元と同じです。そのぶん、Google の woff2 ツール(glyf を変換して格納する)より数%〜2割ほど大きくなることがあります。
  - 一般的な WOFF2(glyf / loca・hmtx を変換して格納したもの)も読み込めます。その場合、glyf / loca は規格どおり組み立て直すので、輪郭・字幅は元と同じですが、バイト列は元の TTF と少し違うことがあります。
- 輪郭の形式は変換しません。TrueType の輪郭のフォントは「TTF」、CFF の輪郭のフォント(OpenType)は「OTF」を選んでください。合わないほうを選ぶと、理由を表示します。
- 複数のフォントをまとめたファイル(TTC / OTC)には対応していません。
- WOFF2 の圧縮・展開は自前で実装しています。既存の WOFF2 ライブラリは実行時に `new Function` を使い、拡張機能の CSP で動かないためです(圧縮には brotli-wasm を使います)。

### アーカイブ

- **中身は変えません。** ファイルの内容・フォルダ構成(空のフォルダを含む)・更新日時・名前をそのまま移します。拡張子の変更は、外側のアーカイブのファイル名にだけ行います(例:`資料.zip` → `資料.tar.gz`)。
- **日本語の名前**:ZIP は UTF-8 で記録し、UTF-8 フラグを付けます。TAR は PAX 形式の拡張ヘッダーに UTF-8 で記録します。UTF-8 フラグのない ZIP(日本語版 Windows の標準機能で作った ZIP など)は、名前を UTF-8 / Shift-JIS から自動で判定して読みます。長い名前(100 バイト超)も扱えます。
- **更新日時**:ZIP は DOS 日時(2秒単位、ローカル時刻)に加えて、秒単位の UTC の時刻(拡張タイムスタンプ)も書きます。TAR は秒単位です。元の ZIP に DOS 日時しかないときは、2秒単位になります。
- **パストラバーサルの防止**:`../` を含むパスや絶対パス(展開先の外にファイルを書き出せてしまうもの)を含むアーカイブは、変換を中止して理由を表示します。
- **上限**:展開後の合計が 1GB を超えるアーカイブは、展開する前に中身の一覧(ZIP)や gzip の記録(TAR.GZ)で確かめて、変換を中止します。
- 対応していないもの:パスワード付き(暗号化された)ZIP、Deflate と無圧縮以外の圧縮方式の ZIP(bzip2・LZMA など)、TAR の中のシンボリックリンク・ハードリンク(ZIP で表せないため含めず、完了時に件数を表示します)、TAR 以外を gzip で圧縮したファイル(`.gz`)。
- ZIP の中の各ファイルは CRC を確かめて読み込み、壊れていれば理由を表示します。ZIP64(4GB 超の項目)の記録も読めます。

## 上限

| 項目 | 上限 | 超えたとき |
|---|---|---|
| 画像ファイルのサイズ | 100 MB | 追加した時点で「対象外」と表示し、変換しない |
| 画像のピクセル数 | 1億ピクセル(例:10000×10000) | 「画像が大きすぎます」として失敗にする |
| ドキュメント・データのファイルサイズ | 50 MB | 追加した時点で「対象外」と表示し、変換しない |
| 音声・動画のファイルサイズ | 500 MB | 追加した時点で「対象外」と表示し、変換しない(変換結果をメモリ上で組み立てるため) |
| フォントのファイルサイズ | 50 MB | 追加した時点で「対象外」と表示し、変換しない |
| アーカイブのファイルサイズ | 500 MB | 追加した時点で「対象外」と表示し、変換しない |
| アーカイブを展開したときの合計 | 1 GB | 展開する前に確かめて、変換を中止する |
| PDF のファイルサイズ | 200 MB | 追加した時点で「対象外」と表示し、変換しない(ページは1枚ずつ処理するので、元のファイルが大きくても扱える) |

## 権限と理由

| 権限 | 理由 |
|---|---|
| `sidePanel` | サイドパネルに変換画面を表示するため |
| `downloads` | 変換したファイルを保存するため(保存ダイアログを出さずに保存し、一括保存ではフォルダを作り、同名ファイルには番号を付ける) |
| `contextMenus` | 画像の右クリックメニューに「ファイル変換」を出すため |
| `offscreen` | 右クリック変換の処理を、画面のない拡張機能のページ(Offscreen Document)で行うため |
| `notifications` | 右クリック変換の完了・失敗を知らせるため |
| `<all_urls>`(任意の権限) | 右クリックした画像をウェブから取得するため |

`<all_urls>` は**インストール時には求めません**。初めて右クリック変換を使うときに、Chrome の確認画面で許可を求めます(`optional_host_permissions`)。許可しなければ、右クリック変換だけが使えず、サイドパネルの変換はそのまま使えます。右クリックの操作から確認画面を出せない環境では、小さな確認ウィンドウを開き、そこで「許可して変換する」を押すと許可を求めます。許可は `chrome://extensions` の「詳細」→「サイトへのアクセス」からいつでも取り消せます。

この権限は、右クリックした画像を取得するためだけに使います。ページの内容を読んだり、ページにスクリプトを入れたりはしません。

## プライバシー

- 変換はすべてこの端末のブラウザの中で行います。ファイルの内容・ファイル名・利用状況を外部に送信しません。
- 右クリック変換では、画像を表示しているサーバーから画像を取得します(ページで画像を表示するときと同じ通信で、ログインが必要な画像のために Cookie も送ります)。それ以外の通信はしません。
- 外部のサーバー(CDN・フォント・解析ツールなど)には一切接続しません。
- 元のファイルを変更・削除しません。

## 既知の制限

- **AVI** と、ブラウザが展開できない映像・音声の方式(DivX / Xvid、WMV、ProRes、AC-3 / DTS など)は変換できません。
- **OGG** は Ogg Opus で書き出します(Vorbis のエンコーダーがないため)。
- **OCR には対応していません。** スキャンした画像だけの PDF からはテキストを取り出せません。
- **メタデータ(Exif など)は保持しません。**
- 画像のアニメーション(GIF / WebP / APNG / AVIF)は静止画にすると最初のフレームだけ、複数ページの TIFF・複数画像の HEIC は最初の1枚だけを変換します。
- **パスワード付き**の PDF・Excel・ZIP は変換できません。
- Markdown → PDF では画像を読み込みません。また、絵文字など Noto Sans JP にない文字は表示されません。
- 右クリックメニューには、画像の形式に関係なく変換先の全形式が出ます(Chrome のメニューは画像の URL で出し分けられないため)。`blob:` URL の画像は変換できません。
- 変換中にサイドパネルを閉じると、変換は中断されます。
- 音声・動画の処理速度は、パソコンの性能やハードウェアの対応状況で大きく変わります。
- 動作を確かめているのは Chrome のみです(Chromium 系の他のブラウザでも動く可能性はありますが、保証しません)。

## 開発

```bash
npm install
npm run build      # dist/ にビルド
npm run dev        # 変更を監視してビルドし直す
npm run typecheck  # 型チェック
```

- TypeScript + Vite。UI フレームワークは使っていません。
- `npm run typecheck` は、拡張機能のコード(`tsconfig.json`)とビルド設定(`tsconfig.node.json`)の両方を確かめます。

### フォルダ構成

```
public/            manifest.json とアイコン(そのまま dist/ にコピー)
sidepanel.html     サイドパネル
offscreen.html     右クリック変換の処理を行う画面のないページ
permission.html    権限の確認ページ(右クリックから権限を求められない環境用)
src/
  background/      Service Worker(右クリックメニュー・権限・保存・通知)
  sidepanel/       サイドパネルの画面
  offscreen/       Offscreen Document(右クリック変換で画像を取得して変換する)
  permission/      権限の確認ページ
  worker/          変換用 Worker
  core/            形式の判定・レジストリ・文字コード・上限など、共通の部品
  dom/             DOM が必要な処理(SVG の描画・保存・Worker の窓口・HTML 変換の入口)
  converters/      変換の実装(image / document / pdf / media / font / archive)
  ui/              共通のスタイルとフォント
```

### 設計方針

- **完全ローカル処理**:ファイルを外部に送らない。依存(wasm・フォント・ワーカーを含む)はすべて同梱し、CDN から取得しない。
- **CSP**:`extension_pages` は `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'` のまま緩めない。`eval`・`new Function`・インラインスクリプト・blob: URL の Worker は使わない(使うライブラリはビルド時に対処するか、採用しない)。
- **最小限の権限**:ホスト権限は `optional_host_permissions` にして、必要になったときに求める。
- **UI を止めない**:重い変換は Worker で行い、進捗とキャンセルを用意する。重いライブラリは使うときだけ動的 import で読み込む。
- **元のファイルを変更しない**。信頼できないファイルを読むので、パースの例外は握りつぶさず、理由付きの失敗として表示する。
- **ファイル名**:拡張子だけを変える(小文字、JPEG は `.jpg`)。同名は `chrome.downloads` の `conflictAction: "uniquify"` に任せる。例外は PDF → 画像の `_001` と、画像を1つの PDF にまとめるときの先頭ファイル名。
- **品質**:劣化しない変換は劣化なし。非可逆形式へは高品質の既定値(JPEG・WebP は 0.95 以上、音声は元のビット率以上)。
- **レジストリ**:変換は「コンバーター」としてデータで登録する(入力形式・出力形式・用途文・実行するエンジン・必要な前処理など)。候補表示・右クリックメニュー・変換の実行はすべてレジストリから作るので、形式を増やすときは `src/converters/<種類>/index.ts` に登録を足し、エンジンを実装する。
- **形式の判定**:拡張子だけに頼らず、先頭のバイト(マジックナンバー)で判定し、中身を優先する(`src/core/formats.ts`・`src/core/detect.ts`)。
- **デザイン**:白い背景・近い黒の文字・細い枠線・小さな角丸(ボタン 8px、カード 12px)・影なし。黒い主ボタンは画面に1つだけ。フォントは同梱の Inter と OS の日本語フォント。値は `src/ui/style.css` の先頭にまとめている。
- 動作確認用の一時ファイル・テストコードはリポジトリに残さない。

- `src/core/registry.ts` が変換の一覧(レジストリ)です。サイドパネルの候補表示、右クリックメニュー、変換の実行は、ここから作られます。
- 変換は Worker(`src/worker/`)で行います。サイドパネルからも、右クリック変換(Service Worker → Offscreen Document)からも、同じ Worker・同じコンバーターを使います。
- 重い処理(HEIC・TIFF・AVIF・Excel・Markdown・YAML・PDF・音声・動画・WOFF2 など)は Worker の中で、使うときだけ読み込みます。HTML の変換だけは DOMParser が必要なため、サイドパネル側で行います。
- pdf.js が実行時に読む資源(CMap・標準フォント・画像デコーダーの wasm・ICC)は、ビルド時に `dist/pdfjs/` へコピーします(`vite.config.ts` の `copyPdfjsAssets`)。
- 音声・動画は `src/converters/media/`(Mediabunny + WebCodecs)です。Mediabunny の MP3 / FLAC / AAC エンコーダーは blob: URL から Worker を作りますが、拡張機能の CSP ではそれができないため、ビルド時に Worker のコードを `dist/assets/mediabunny-*-encoder.worker.js` として書き出して読み込むよう書き換えています(`vite.config.ts` の `mediabunnyEncoderWorkers`)。
- Markdown → PDF のフォントの縮小は `src/converters/pdf/ttfstrip.ts` です(pdf-lib のサブセット機能は Noto Sans JP で文字が欠ける不具合があるため使っていません)。
- 保存は `src/dom/save.ts` の `saveOutputs`(変換結果のリストを受け取り、個別・フォルダ・ZIP で保存)に集約しています。個別保存は `chrome.downloads`、一括保存は File System Access API(`showDirectoryPicker`)で選んだフォルダへの書き込みです。
